# P3 Input Specification

## 1. Candidate Pairs Input (`candidate_pairs.tsv`)

### Overview
Generated by Stage P2 (`candidate_generation.py`), this TSV file lists candidate matching records from Source 2 and Source 3 for every Source 1 entity.

### File Details
- **File path:** `output/candidate_pairs.tsv`
- **Format:** Tab-separated values (`.tsv`), UTF-8 encoded.
- **Header:** `source1_entity_id\tcandidate_entity_ids`

### Column Schema
| Column Name | Type | Description | Constraints |
|---|---|---|---|
| `source1_entity_id` | `str` | Unique record ID for Source 1 | Non-null, prefix `S1-`, appears exactly once per S1 entity |
| `candidate_entity_ids` | `str` | Comma-delimited list of candidate entity IDs | Can be empty for singletons; all IDs prefixed with `S2-` or `S3-`, sorted alphabetically |

### Example Rows
```tsv
source1_entity_id	candidate_entity_ids
S1-714132312	S2-321151613,S2-817362843,S3-911823714
S1-106407869	S3-106407869
S1-156285671	
```

## 2. Normalized Records Input (From P1 Preprocessing)

### Overview
P1 provides the preprocessed record representations accessible via `iter_preprocessed_file` from `preprocessing.py` or preprocessed DataFrames.

### Schema per Record
| Field Name | Type | Description | Origin |
|---|---|---|---|
| `entity_id` | `str` | Unique record ID (`S1-...`, `S2-...`, `S3-...`) | Raw TSV |
| `business_name` | `str` | Original business name | Raw TSV |
| `business_address` | `str` | Original business address | Raw TSV |
| `country` | `str` | Country code/string (e.g., `US`, `India`, `France`) | Raw TSV |
| `name_clean` | `str` | Lowercased, Unicode NFC normalized, punctuation-cleansed | P1 Preprocessing |
| `name_compact` | `str` | `name_clean` with whitespace removed | P1 Preprocessing |
| `name_token_key` | `str` | Space-separated alphabetically sorted name tokens | P1 Preprocessing |
| `address_clean` | `str` | Lowercased, Unicode NFC normalized address | P1 Preprocessing |
| `address_token_key` | `str` | Space-separated alphabetically sorted address tokens | P1 Preprocessing |
| `country_clean` | `str` | Normalized casefolded country string | P1 Preprocessing |

## 3. Ground Truth / Labels Connection

- **Training Pairs:** Pairs generated from candidate retrieval on training records. Positive matches are confirmed entity links, and negative pairs are non-matching candidates retrieved during blocking passes.
- **Connection Mechanism:** Pairs $(A, B)$ are formed by joining $A$ (`source1_entity_id`) and $B$ (`candidate_entity_id`) with their respective P1 normalized record features.
